# Playbook: Configuration Analysis

适用于以配置/声明为核心驱动行为的目标（服务发现、特性开关、地址、认证声明）。

## 何时用
- 目标行为大量由配置驱动（如服务地址、认证方式、可调用实体、功能开关）。
- 需要理解"这个系统如何被配置、配置如何生效"。

## 配置来源分类
| 来源 | 性质 | 可靠性 |
| -- | -- | -- |
| 随产品分发的配置文件 | 静态声明 | 高（描述意图），但可能被覆盖 |
| 用户数据目录/本地存储/缓存 | 运行时状态 | 高（接近事实） |
| 云端拉取的配置 | 运行时覆盖 | 可能改写静态值 |
| 环境变量 / 命令行参数 | 运行时覆盖 | 优先级高 |
| 默认内置常量 | 静态 | 低（易被覆盖） |

## 工作流
1. **枚举配置面**：找出所有配置来源（文件、存储、缓存、环境、云端）。
2. **提取关键字段**：服务地址、认证配置块、域名/路径白名单、可调用实体清单、开关。
3. **建立配置生效优先级**：什么覆盖什么（通常：内置常量 < 分发配置 < 用户存储 < 环境/云端）。
4. **对照运行时**：用运行时存储/缓存确认"实际生效值"，标注与静态声明的差异。
5. **若行为由云端配置驱动**：还原配置获取的请求，确认它是否改写本地静态值。

## 关键认识
> 配置是"声明"不是"事实"。同一地址在静态配置、用户存储、云端配置里可能是三个值。
> 以"运行时实际生效的值"为准，并记录它的来源链。

## 常见错误
- 只读分发配置文件就下结论，忽略用户/云端/环境覆盖。
- 不建立"覆盖优先级"就判断哪个值生效。
- 把配置字段名当作实际行为（字段名≠行为）。
