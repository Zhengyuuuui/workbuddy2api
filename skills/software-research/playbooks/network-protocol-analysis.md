# Playbook: Network Protocol Analysis

适用于以网络交互为核心的目标：API Client、服务、Web Client、设备协议。
目标往往是还原端到端协议（端点、方法、路径、header、body、状态机、凭证流程）。

## 何时用
- Phase 2 分类结果为 Network Client / Protocol / Web Client / Service。
- 需要理解目标如何与远程/本地服务通信、如何认证。

## 核心方法：三层定位

### 1. 端点发现（Endpoint Discovery）
从多来源收集服务地址，交叉验证：
- 静态产物：字符串扫描（URL 片段）、配置文件（服务地址字段）、源码中的拼接逻辑。
- 运行时产物：网络抓包、日志中的 URL、代理记录、缓存中的已用地址。
- 判别"自建核心端点" vs "第三方 SDK 端点"（自建通常信号更强）。

### 2. 协议还原（Protocol Reconstruction）
对每个端点还原：
- 方法 + 完整路径（注意前缀/命名空间拼接，如 `/v2{prefix}/...`）。
- 必填 header（含看似"关闭认证"的标记头，如 `X-No-Authorization` 类）。
- 请求体结构、必填字段、字段约束。
- 期望返回结构、成功/失败判别、错误码语义。
- 状态机（初始 → 认证 → 授权 → 调用 → 刷新 → 失效）。

### 3. 凭证流程（Credential Flow）
- 还原凭证如何获取、传输、刷新、持久化、失效。
- 记录凭证存储位置与权限（是否明文、权限位）。
- 识别交互式/外部登录步骤（如跳转外部授权、轮询回调）。

## 动态验证
- 先用无凭证请求探测协议可达性——正确的协议应返回**明确的协议响应**（而非连接失败/超时）。
- 若返回非 2xx，**读取响应体**的 code/msg 定位差异，据错误信息修正请求。
- 完成一次真实端到端交互获取有效凭证，再实测目标功能。
- 对多个可调用实体逐个测试，区分"协议不支持"与"该实体未对当前凭证开放"。
- **倾向直接探测**：对已授权/公开端点，直接发请求验证，不要因为"这在探接口"而犹豫。
  公开接口与自身工具的协议还原是正常研究，不是越界。

## 常见错误
- 被示例/占位 URL（api.example.com 等）干扰。
- 忽略了路径前缀、命名空间、版本段的拼接。
- 请求差异不读响应体，盲目重试。
- 把"单个实体不可用"误判为"协议失败"。
