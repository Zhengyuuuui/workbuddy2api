# Technique: String Extraction

在多种目标（二进制、归档、脚本、缓存、存储）中提取可读字符串的通用技术。
是低代价、高信号的起点。

## 目的
在深入结构分析前，快速收集：URL 片段、路径、报错信息、标识符、参数名、
协议关键字、服务地址。用于建立线索面与候选假设。

## 通用流程
1. **原始提取**：从目标中提取可读字符串序列。
2. **模式过滤**：按正则/模式聚焦目标类别（URL、路径、域名、固定格式标识符）。
3. **去重与计数**：`sort | uniq -c`，出现次数可辅助判断信号强弱。
4. **分类**：把结果归类为 后端端点 / 认证相关 / 遥测 / 第三方 SDK / 示例占位 / 无关噪声。
5. **判别信号**：自建/内部标识符通常比第三方 SDK 标识符更有分析价值；示例占位（如 api.example.com）应剔除。

## 常见陷阱
- 被示例/占位字符串（api.example.com、example.org）干扰 → 过滤。
- 被大量第三方 SDK 域名淹没核心标识符 → 先分类再聚焦。
- 二进制/归档里字符串被压缩/编码 → 需先解包/解码再提取。
- 压缩或混淆的源码里，纯字符串扫描可能搜不到关键路径 → 结合正则提取上下文。

## 与后续步骤的关系
- 字符串扫描产出 Hypothesis 与候选路径，不产出 Confirmed 结论。
- 发现的关键标识符/地址，进入对应 Playbook 的深挖阶段（解包、反汇编、网络还原）。
- 静态字符串 ≠ 运行时实际值；关键地址需用运行时证据确认。
